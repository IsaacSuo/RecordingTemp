多相机录像台 2.4 · MindVision + ZED · 研究采集与高级参数
============

打开
  双击 Y:\多相机录像台.lnk。
  只想先体验界面：双击程序目录里的“模拟演示.lnk”。
  模拟模式有两路生成的画面，不会连接实际相机，输出目录标有 DEMO。
  已打开的旧窗口不会自动热更新；停止保存后关闭旧窗口，再双击入口。

每台相机一个进程（2.4，2026-10-20）
  每台 MindVision（mv_worker.py）和每台 ZED（zed_worker.py）都在自己的进程中运行。界面只负责发命令、收事件和预览。
  某台相机或 SDK 出错只影响自己的进程；录制参数、文件格式和完整性检查与以前相同。
  各进程的日志在程序目录 logs 下。
  实测：两台 MindVision 加一台 ZED 同时录 60 FPS MP4 60 秒。
    改造前：两台 MindVision 接收约 67 FPS，各补帧约 240（6.6%）。
    只改成独立进程：接收约 75 FPS，各补帧约 44（1.2%）。
    再提高进程优先级并关闭节能降速（Windows 会把没有窗口的进程放到能效核上，颜色转换因此慢一倍）：
    两次实测都是接收 76.42 FPS，补帧 0，SDK 丢帧 0，完整性检查通过；颜色转换回到每帧 5.3–6.5 ms。
  相机进程启动时会在下方消息显示是否已提高优先级。
  MindVision SDK 的限制：同一时间只能取出一帧（上一帧未释放时取下一帧返回“正忙”），颜色转换也不接受拷贝出来的原始数据。
  因此颜色转换无法移到单独线程与取帧并行，这项改动未做。

ZED 2i（2.4 新增）
  “搜索相机”同时查找 MindVision 和 ZED，ZED 显示为单独卡片，与其他相机一起一键开始、停止。
  ZED 录成 SVO2（左右目未校正原图、IMU、逐帧时间戳），不生成 MP4，不补帧。
  卡片上可选：
    模式：默认 HD1080 @ 30，也可选 HD720 @ 60 等。
    压缩：默认 H.264 有损；可改 H.265 有损、H.265 无损、H.264 无损。
    翻转：默认按 IMU 自动判断是否倒装；立体相机不做镜像。
  模式和翻转是连接参数：断开后修改，重新连接才生效。压缩可在每次开始前修改。
  曝光、增益为 ZED 自己的 0–100 单位，两项都留空表示自动。“自动白平衡并锁定”会等色温稳定后锁定。
  点击开始时，自动曝光、增益和白平衡会锁定为当时的值，录制期间不再读写相机参数（实测读参数会造成丢帧）。
  ZED 在独立进程中运行（.venv-zed），ZED 出错不会拖垮 MindVision；日志在程序目录 logs 下。
  每台 ZED 的保存内容：
    <序列号>.svo2               双目视频与传感器数据
    <序列号>.received.jsonl     每个收到的帧的时间戳、取帧耗时和 SDK 丢帧计数
    <序列号>.calibration.conf   出厂标定文件副本（SVO2 本身不含标定）
    <序列号>.json               参数快照、锁定值、完整性统计
    <序列号>.integrity.txt      可直接阅读的完整性报告
  完整性报告把缺帧分开统计：
    1. 相机 / SDK 缺帧：按相机时间戳缺口估算，帧没有到达程序。
    2. 程序处理不足：程序两次取帧间隔超过一个周期，由此丢失的帧。
    3. MP4 补帧：SVO2 不适用。
  SDK 自带的丢帧计数会被清零，只作参考；重复返回的同一帧会被剔除。
  ZED 的“30 fps”实测约 29.86 fps，报告中写明实际帧率与标称值的差别。
  停止时会多录 1 帧作为填充（日志中 stop_padding=true，不计数），用来抵消 SDK 5.5 可能丢掉文件最后一帧的问题。
  完整逐帧核对（只读）：
    & '.\.venv-zed\Scripts\python.exe' zed_worker.py --verify-svo '<序列号>.svo2'
  连接注意：
    ZED 接机身 USB-A 口时实测 60 秒 0 丢帧；接扩展坞时约 2% 缺帧。
    机身 A 口共用一条 5 Gbps 链路，多台相机需要分开接。

编码与写盘（2.3）
  启动录制前实际探测 NVIDIA H.264 NVENC；可用时优先使用硬件编码，
  不可用时使用 libx264 ultrafast / CRF 18 软件编码，文件可能更大。
  当前编码器显示在下方消息，并记录在 JSON 的 encoder 中。硬件编码采用
  p4 / VBR CQ 18；CQ 与 CRF 属于不同编码器参数，不代表完全相同画质。
  逐帧元数据在独立线程写盘；旋转/镜像由预览线程与编码器分别执行，
  取帧线程不再做额外方向变换。已验证两条路径的像素方向一致。
  编码队列有界且入队不等待，允许编码器启动时短暂积压；队列满时明确
  停止并保存已有帧，避免等待编码导致取帧变慢、再不断补入重复帧。
  1920x1200 下最多缓存 38 个输出帧，实际占用取决于独立源帧数量。
  JSON 中 source_sha256 固定为程序启动时的文件哈希，避免旧窗口在磁盘
  更新后错误记录成新文件版本。更新后仍须重开，标题应显示 2.3。

录制性能与诊断（2.2）
  默认旋转 180° + 水平镜像改为等价的逐行翻转，减少全分辨率像素复制。
  预览转换和缩略图生成在独立线程进行，只保留最新预览，不积压预览队列。
  画面上的“接收 FPS”是程序近期实际取到的速度，不是传感器标称帧率。
  开始录制时重置测速窗口，JSON 的 source_fps 是整段接收帧的平均帧率。
  MP4 的重复计数来自时间戳重采样，不等于硬件丢帧数。固定时间区间内
  保留第一帧的策略仍然存在；平均接收速度达到目标也可能因间隔波动而重复。
  capture_performance 记录取帧、SDK ISP、像素复制、方向变换及入队等耗时；
  encoder_performance 记录编码入队等待和管道写入耗时。单位为 ms，包含
  调度等待；取帧耗时包含等待下一帧，嵌套阶段不能直接相加。
  原有录像文件不修改。离线优化结果不代替实机持续帧率验收。

放大对焦
  每路预览旁点击“放大对焦”，也可双击预览画面，打开独立实时窗口。
  默认 100% 原始像素；可选适应窗口、200%、400%，支持滚轮切换倍率。
  按住鼠标左键拖动画面查看局部，“回到中心”恢复中心位置。
  F11 或全屏按钮切换全屏，Esc 退出全屏，也可直接调整窗口大小。
  放大窗口接收原始分辨率的处理后画面，不是把主界面小缩略图拉大。
  200%/400% 按像素放大，不产生新细节；对焦优先用 100% 判断。
  预览约 10 FPS，录制时也可查看；缩放、拖动不改变录制分辨率或方向。
  关闭放大窗口恢复缩略图传输，断开相机时自动关闭。

高级参数与方向（2.1 新增）
  每台相机卡片点击“高级参数…”，分为曝光与方向、色彩与亮度、处理与速度。
  主界面的旧旋转复选框已移除。连接后的预览和 MP4 默认旋转 180°，并开启水平镜像。
  在高级面板选择 0° / 180° 或水平/垂直镜像会立即应用；其他参数编辑后
  点击“应用修改”。应用后显示实际读回值，设备量化造成的差异会提示。
  方向变换在 SDK 彩色处理后由程序执行，预览和 MP4 使用相同像素结果。
  研究 RAW 保留 SDK 返回的原始字节，方向设置另记入 application_orientation。
  高级面板按相机能力与实际读回结果显示范围，不支持或读不到的项目禁用。
  可用项目包括曝光、模拟增益、RGB 数字增益、LUT 模式/预设、Gamma、
  对比度、饱和度、黑白电平、锐化、2D/3D 降噪、坏点校正、已有平场校正、
  采集速度档位与 Bayer 转彩色算法；具体以设备显示为准。
  Gamma 使用 SDK 整数单位；Gamma/对比度需要动态 LUT，预设曲线需预设 LUT。
  一次白平衡在下一张图像处理后重新读取参数；操作时使用中性白/灰目标。
  3D 降噪混合多帧，运动测量通常关闭；修改其开关或帧数后使用等权重。
  平场开关只启用已加载且有效的标定，不执行新标定、不生成标定文件。
  录制期间参数锁定。模拟模式验证参数读写与方向，不能模拟真实 ISP 色彩。
  不增加 ROI 设置。

研究模式
  在模式选择框中选择“研究 RAW（全部接收帧）”，填写实验编号。
  原始数据保存所有应用接收到的帧，不补帧、不按 30/60 FPS 抽帧。
  此时 MP4 FPS 选项停用；真实采集速度由曝光、相机速度档位及硬件决定。
  不同时生成 MP4，仍提供实时预览。需要 30/60 FPS 普通视频时选 MP4 模式。
  每台相机的数据集位于批次目录下的 <序列号> 文件夹。
  详见同目录 RESEARCH_DATA_格式说明.txt。

实验信息
  顶部可填写实验编号、样品、重复编号。“更多实验信息”填写操作者、
  镜头、光圈、光源和备注。每台相机还可填写位置/用途。
  镜头和光源信息由用户填写，不是相机自动测量值。
  开始时冻结本次填写内容，存入 batch.json 和每台相机的 JSON。

参数预设
  连接相机、调好画面后点击“保存预设”，先应用界面曝光/增益/旋转，
  再把 SDK 配置和读回参数保存到程序目录 presets 下的新时间文件夹。
  下方信息会给出路径。不同相机各保存一份，以序列号匹配。
  “加载预设”选择该文件夹，加载当前勾选相机的配置并读回设置。
  模拟预设与实机预设互不混用；不同序列号不能混用。
  .config 与 .preset.json 应一起保存；软件旋转和镜像存于后者，单独 SDK
  配置不包含这些应用层设置。加载预设后方向按预设恢复，不强制回到 180°。
  多相机分别完成保存/加载，每台结果在下方报告；不是跨设备原子操作。
  预设不恢复实验编号，避免把上次实验信息误当成新实验。
  本版仍只使用连续采集；加载预设后固定为手动曝光和手动白平衡。
  若配置依赖外部平场/标定文件，应另行保存这些文件；本版会记录可读回
  的校正状态/路径，但尚不自动打包所有外部校正资源。

界面（2.4 新版）
  顶栏：录像状态和计时、相机概况（是否有相机需关注）、保存盘剩余空间；录像时另显示写入速度和估计可录时长。
  左栏，按顺序操作：
    1 相机：搜索、连接所选、断开；每台相机一行，可勾选，彩色圆点表示状态。
      灰色为未连接，绿色为预览中，红色为录像中，黄色为需关注。
    2 录制设置：模式、MP4 帧率、保存位置、参数预设。
    3 实验信息：实验编号、样品、重复编号；“操作者、镜头、光源、备注…”填写更多信息。
    最下方是开始 / 停止按钮，快捷键 F9。
  中间：所有相机的实时画面。列数自动选择，让全部相机不用滚动就能看到，画面尽量大。
    边框：红色为录像中，黄色为录像中出现缺帧 / 补帧或连接异常，绿色为当前选中。
    录像结束后边框恢复正常；上次的结果留在画面下方的文字里（有缺帧时为黄色，失败为红色），详见结果窗口。
    连接异常的相机会保持黄色标记，直到重新连接。
  右侧参数面板：点相机画面或“参数”打开，包括：
    位置 / 用途（会显示为相机名称）、曝光、增益、白平衡、高级参数。
    ZED 另有分辨率与帧率、翻转、SVO2 压缩。
  双击画面或点“放大对焦”，打开原始分辨率的对焦窗口。
  底部状态栏：显示最新消息，“消息记录”展开全部记录。
  每批结束后弹出结果窗口：逐台列出帧数、缺帧 / 补帧和检查结果，可直接打开目录。
  高分辨率缩放屏幕（如 175%）下文字清晰显示。

第一次录像
  1. 退出官方软件和 ZED Explorer，避免占用相机。
  2. 左栏点“搜索”，勾选相机，点“连接所选”。
  3. 点某台相机的画面打开右侧参数面板，调曝光、增益后点“应用”。
     MindVision 默认旋转 180° 并开启水平镜像，改方向在“高级参数与方向…”里。
     一次白平衡：在正常照明下让中性白 / 灰目标充满画面，再点击按钮。
  4. 选择模式和保存位置；MP4 模式选 30 / 60 FPS。
     30 FPS 可先用 20 ms 曝光，60 FPS 可先用 10 ms；切换到 60 FPS 时，会把过长的曝光改为 10 ms。
  5. 按“开始录像”或 F9，所有勾选的相机一起开始；再按一次停止，等结果窗口出现。

保存内容（2.4：每台相机一个子文件夹）
  每次录像新建一个日期时间文件夹，不覆盖以前的录制：
    <批次>/batch.json                    本批实验信息、各相机结果、导出结果（exports）
    <批次>/mindvision_<序列号>/           MindVision 的文件（见下）
    <批次>/zed_<序列号>/                  ZED 的文件：
        <序列号>.svo2                     原始双目录像（左右目未校正、IMU、时间戳）
        <序列号>.received.jsonl           逐帧时间戳与取帧记录
        <序列号>.calibration.conf         出厂标定副本
        <序列号>.json / .integrity.txt    参数快照与完整性报告
        export/                           录完后自动导出（后台进行）：
            left.mp4、right.mp4           校正后的左右目视频（H.264）
            depth.mp4                     仅在选了深度时生成，放在 export_NEURAL 或 export_NEURAL_LIGHT 文件夹
            timestamps.csv                每个视频帧对应的 SVO2 帧号、相机时间戳，以及是否为补帧
            export.json                   导出设置、帧数、补帧数、耗时
  ZED 导出设置在左栏“ZED 录完后自动导出”：默认只导出左右目视频，也可选 NEURAL（效果最好、较慢）
  或 NEURAL_LIGHT（较快）计算深度。导出的视频按相机实际帧率（约 29.86 FPS）编码，时长与实际录制一致；
  相机缺帧处重复上一帧，并在 timestamps.csv 中标记 repeated=1，所有真实帧都会写入。
  导出期间开始新录像，导出会暂停，录完后从头重新导出；退出程序会停止未完成的导出。
  SVO2 原始文件始终保留，可以手动换一种方式重新导出：
    & '.\.venv-zed\Scripts\python.exe' zed_export.py '<序列号>.svo2' --depth NEURAL
  实测（60 秒 1080p 录像，2026-10-20 优化后）：只导出左右目约 1 分钟，不慢于实际录制时长（优化前约 2 分钟）。
  最多 3 台 ZED 同时导出，每台仍快于实时，总吞吐约为逐台导出的 2 倍。
  导出进程同样提高优先级并关闭节能降速；解码与写入编码器并行进行。
  NEURAL 或 NEURAL_LIGHT 深度在优化前约 3 分钟，优化后未复测。
  每种深度模式第一次使用时，要先下载模型并针对显卡优化，约 20–30 分钟（需联网），之后不再需要。
  本机两种模型已于 2026-10-20 装好。深度结果的正确性还需要用光线充足的场景录一段确认。
  MindVision 子文件夹内容：
  <相机序列号>.mp4          H.264 视频，无音频
  <相机序列号>.config       此次使用的 SDK 相机参数
  <相机序列号>.json         帧数、时长、补帧数、源帧率和错误信息
  <相机序列号>.frames.csv   每个已写入视频帧的相机时间戳及补帧标记
  <相机序列号>.ffmpeg.log   编码日志
  <相机序列号>.received.jsonl  每个接收帧的元数据和是否选入 MP4
  <相机序列号>.end.config   停止时的 SDK 参数（设备断连时可能不可用）
  <相机序列号>.integrity.txt  MP4 采集完整性报告
  batch.json                本批所有相机的录制结果
  点击“打开目录”会打开最近一次录像文件夹。

画面与帧率
  保留相机原来的分辨率。连接时设置为连续采集、手动曝光、Normal 档
  （如果相机提供此档），曝光初始值不超过 20 ms。
  使用 SDK 的颜色处理结果，保留已加载的白平衡、伽马和数字增益等。
  开始采集时锁定手动曝光、手动白平衡，避免拍摄中自动漂移。
  不额外套用之前 RAW 视频的提亮/调色滤镜。
  每台相机可以独立设置曝光、模拟增益、方向与高级处理参数。
  本版不提供 ROI/分辨率设置；如需改变，可先在官方软件中设置并保存。

  “录像 FPS”是输出视频帧率。根据每台相机自己的时间戳选帧，保持
  正常播放速度；如果源帧率不足，会重复上一帧并在界面和日志明确计数。
  “补帧 0”仅表示输出没有重复帧，不等于硬件采集零丢帧。
  不做多机帧同步，不保证各视频第一帧的曝光时刻一致。
  预览约 10 FPS，以减少显示开销；录像和采集帧率另行统计。

  录像前请确认采集 FPS 不低于目标。全分辨率、多相机同时 60 FPS
  能否长期稳定，取决于 USB 控制器、CPU 和磁盘，尚未进行实机验证。
  编码/写入持续跟不上或某台相机断连时，程序停止本批录像并保存
  能保存的视频，在下方报告错误。供帧不足的补帧会单独告警。

退出与参数
  “断开全部”会释放相机，之后可以再使用官方软件。
  关闭窗口会先停止录像、完成保存、恢复连接前的相机参数，然后退出。
  正常退出时恢复连接前的参数；当次 SDK 参数保存在录像旁的 .config，
  应用层方向保存在 JSON 元数据的 application_orientation 中。
  如果恢复失败，错误信息会给出临时备份位置，便于恢复。
  正常退出时请等待窗口自行关闭。强制结束进程/断电可能损坏正在写的 MP4。
